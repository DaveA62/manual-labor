# Manual Labor

Read [docs/ART_DIRECTION.md](docs/ART_DIRECTION.md) before UI or illustration changes.

- React, TypeScript, Vite, CSS, and SVG. Avoid new dependencies unless necessary.
- Identity: **Questionably Functional**. Used industrial equipment, layered vectors, bold charcoal outlines, repaired mint machinery, cream plates, orange controls, restrained red warnings. Flat fills, exposed bolts, nearly square panels. No glossy UI, emoji icons, rounded dashboard cards, or marketing layouts.
- Tokens: `src/tokens.css`. Barlow Condensed for headings/labels; IBM Plex Sans for UI and numbers. Self-host fonts; retain licenses. Reuse `src/ui/` controls and pagination.
- Writing: functional labels, numbers, and one short instruction when needed. No motivational/filler copy or forced jokes. Deadpan humor is sparse and confined to equipment/environmental labels.
- Primary screens fit one visible viewport. Use `100dvh` with fallbacks, all safe-area insets, zero page overflow, and `min-height: 0` / `min-width: 0` in the frame. Compact persistent mobile bottom navigation; desktop/short-landscape side rail.
- Workshop keeps every interactive part visible. Compact Modifications is a contained modal; measured wide Workshop uses the same panel inline beside the machine. Storage uses a measured paginated bay grid; Catalog selects one entry per page. Never solve capacity or extra upgrades with a scrolling primary screen. Secondary long text may have its own bounded scroll region.
- Keep targets at least 44×44px. Remove decoration before shrinking controls. Preserve mouse/touch Pointer Events, capture, cancellation, and screen-to-SVG conversion. Prevent browser overscroll, selection, and touch callouts during gameplay. Honor reduced motion.
- Storage: 430ms touch hold; screen-owned capture survives pagination; hover enabled page arrows for 550ms to turn pages while dragging. Keyboard arrows cross pages with focus following the same machine. Reordering changes slots only.
- Money Press artwork lives in `src/components/press/Parts.tsx`; damped presentation motion in `useMechanicalMotion.ts`; pointer handling in `Press.tsx`. Preserve the 720×510 coordinate contract and 44px responsive hit areas. Upgrade assemblies read only the selected instance. Cosmetic motion never advances production.
- Read `docs/TECHNICAL_ARCHITECTURE.md` before runtime/platform changes. React owns all UI and navigation; renderers receive `MachineRendererProps` and a stable, scoped `MachineRuntime`. Send manual intent and cosmetic feedback only; never mutate snapshots or tick production from an animation.
- `src/platform/` owns storage, lifecycle/monotonic time, and audio/haptics. Choose an adapter before mounting React; no browser/native SDK calls in the pure reducer, simulation, definitions, or runtime contracts. Preserve the existing save key and explicit legacy migrations. Suspend/resume resets the foreground clock. Offline earnings are claimed through `game-sync` using server timestamps; device-only offline rewards are quarantined.
- SVG remains the production renderer. Phaser 3.90 is isolated in `src/experiments/phaser/`, loaded only behind `import.meta.env.DEV` via `?renderer=phaser` or the development Settings toggle. No eager imports, physics, renderer-specific game rules, or native packaging projects. Guard async setup and dispose canvases/listeners on unmount. Share parts/gesture math, 720×510 logical coordinates, tier finishes, reduced motion, and screen-sized targets. Verify production output excludes Phaser.
- Future Capacitor/desktop wrappers preserve the React UI and pure game core. Add host adapters when implementing those targets; async native storage needs hydration, ordered durable writes, and error reporting before it can satisfy the save lifecycle.
- Production rules, economy, and save validation stay in `src/game/`. Screens render instances and dispatch actions; a single simulation clock owns all production independent of mounted UI.
- Money Press phases: feed → raise → stamp → lift → collect. Only collection pays. Direction alternates after collection. Automation is per instance; Auto Stamper enables automatic stamping. Hidden-browser foreground ticks stop. Server offline simulation uses the same rules with a base eight-hour cap plus permanent Service capacity; Collect only acknowledges an already-applied report.
- Prestige is a tier within a family (`definitions.ts`), never a second machine type. Use shared tier/price/refit selectors; only the reducer charges fees and checks the confirmed source tier. Refit resets upgrades/cycle, preserves IDs, array order (serial), slots, and lifetime records. Cash → Silver → Gold requires the four automation upgrades; printing is optional.
- Finishes scope machine surface tokens on the shared SVG assemblies/thumbnails. Keep charcoal structure, orange controls, wear, and all hitboxes/animations intact across tiers.
- Persist validated instance progress, slot order, and economy. Preserve v1/v2 migration to the initial family tier; v3 stores and validates per-instance tier IDs; v4 adds Bottler physical state and cent-accurate currency without changing old machine data. Visual effects never award cash or drive simulation. Screen/page/overlay transitions must not reset progress.
- Run `npm test` and `npm run build`. Verify Workshop, Storage, Catalog, and Modifications at phone/short-landscape/desktop sizes: no page overflow, reachable controls, intact gestures, cross-page rearranging, and unchanged saves. Report physical touch testing limits.
- GitHub Pages uses `/manual-labor/`; update the Vite base and favicon path if renamed. Keep temporary QA fixtures out of commits/builds.

- Task 07 cloud conventions: read `docs/SUPABASE_SETUP.md` before authentication, saves, deployment, or economy changes. Pin Supabase SDK versions; keep only URL/publishable key in Vite and repository variables. Never expose privileged keys.
- Guest conversion uses Google `linkIdentity` or verified email `updateUser` on the same UUID. Existing-account sign-in is separate. Never automatically merge saves or overwrite a cloud account after an identity collision.
- `GameSession` owns optimistic local play, per-account/window journals, cache/recovery, and synchronization. `game/codec.ts` and `cloud/replay.ts` are React/DOM-free and shared by the Edge Function. Preserve v1/v2/v3→v4 migration and bump `RULES_VERSION` with game-rule changes.
- Cloud writes replay intent through the shared reducer. Database timestamps, compare-and-swap revisions, transaction receipts, and row locks own authoritative offline production. No arbitrary client wallet updates; initial legacy import is a one-time documented trust exception. No claim of cheat-proof human input.
- Keep all exposed player tables RLS protected with owner reads and no client writes. Backend RPCs are service-role-only SECURITY INVOKER. Verify JWT users server-side; never authorize with user_metadata or a user ID from the body. Run security/ownership, replay, concurrent claim, migration and offline cap tests before deployment.
- Conflict resolution preserves a recovery copy and requires choosing cloud or an isolated device fork. Unsynced action receipts must survive network interruption. New machine families need shared server/client simulation and validation before cloud support.
- Account and Shift Report are contained equipment dialogs. Paginate report rows, preserve 44px controls, and never grant cash from Collect/dismiss. Future native hosts provide auth redirects/session storage and lifecycle adapters without moving gameplay into renderers.

- Bottler conventions: read `docs/BOTTLER.md`. `game/bottling.ts` owns load → fill → transfer → cap → collect, capacity-normalized flow/drip, regulated payout and deterministic cycle sizes. Keep balance/physical values in `src/config/machines/`; cosmetic SVG motion never advances production. A manual valve may fill/spill unattended but never auto-transfer or pay.
- Use schema 5 and rules version 3 for new saves/replay (v4/rules 2 are the pre-Retirement baseline). Preserve original save keys, legacy `bills` aggregate-unit field and IDs. Monetary fields accept exact cents; production counts stay integers. Do not round Bottler quality payouts to whole dollars.
- Bottler SVG parts live in `components/bottler/Parts.tsx`; input in `Bottler.tsx`. Preserve rotary-angle input, end-stop tolerance, residual drip lock, expanded 44px targets, pointer cancellation, spring return and keyboard alternatives. All four Bottler upgrades are required for refits. Update server dependencies/migration alongside new family rules; reject schema downgrades.

- Task 09: read `docs/CONFIGURATION.md` before tuning. Machine configuration lives in `src/config/machines/`, economy in `config/economy.ts`, offline cap in `config/production.ts`, UI dimensions/timing in `config/ui.ts`. `game/definitions.ts` is a registry/re-export, not another balance source. Browser and Edge Function import the same values. Preserve schema/rules versions when refactoring unchanged values.
- Important normal text needs at least 4.5:1 contrast; large text needs 3:1. Use charcoal on solid cream plates, or cream on charcoal readouts. `SvgPlate`/`SvgIdentityPlate` own SVG information surfaces. No important labels over paint, pipes, moving bills or transparent vessels. Protect padding and full movement envelopes in every tier/upgrade combination.
- Questionable engineering is deliberate, legible construction. Accidental tangencies, clipped text, label-crossing cables and ambiguous component overlaps are defects. Decorative SVG layers have `pointerEvents="none"`; control hit regions and screen-to-SVG mapping remain authoritative. Resize cancels transient gestures, never production.
- Wide Workshop is selected from measured available width AND height (`UI.wide`), with roughly 62.5% machine / 37.5% management. Reuse `Modifications` inline above embedded paginated `Storage`; keep both visible, purchases reachable and quick switching scoped to the instance. No duplicate reducer, simulation clock or purchase logic. Narrow/short windows retain compact navigation and native maintenance modal. No primary page scrolling.
- Reusable controls/status/pagination/cards share equipment styles; UI animation variables originate in `config/ui.ts`, palette/material/typography tokens in `tokens.css`. Run contrast/layout checks along with gameplay tests. Real touchscreen verification must be reported separately.

- Retirement (Task 10): read `docs/RETIREMENT.md`. Schema 5/rules 3 add optional account `service`; absent means zero retirement history. Keep stable IDs, point accounting, history, discovery and career/session IDs in the pure shared Service modules. Never import permanent Service state from a client initial save.
- `SyncRequest.command` is the only Retirement/skill/Begin Career path. Authenticate owner, replay trusted elapsed time, validate shared rules, then use the existing locked revision/receipt transaction. Persist the reset before the cinematic. No optimistic point grants, zero-point retirement, local-only Retirement, automatic merges or replayed retired factories. Interrupted requests reuse UUIDs; use session/source-level guards as well as receipts. Old clients cannot erase Service.
- Grouped stats live in `game/service/stats.ts`; both families, all price displays/reducer charges, foreground and offline production use them. Add within groups, multiply groups, quality separately, cent rounding per unit. Speed modifies duration, preserves minimums, and splits at Seniority expiry. Permanent bays never raise the paid-bay price exponent. Keep conversion/effect/cap values in `config/retirement.ts` and `config/continuum/skills.ts`.
- Continuum is retirement-session-only, world-space SVG with authored coordinates, separate discovery edges and AND/OR eligibility, pan/pinch/pointer-centered zoom, bounded camera and 44px targets. Its dark violet/silver/pale-gold atmosphere deliberately excludes factory chrome. Compact inspector and persistent Begin Career stay within the viewport. Account may show only a read-only purchased-skill summary during work.
- First CRT retirement sequence is finite, persisted-state-driven and has no flicker. Cut factory audio through the platform port; reduce motion to a short still/fade. Later transitions are skippable. Cosmetics never award Years or decide transaction completion. No respec, placeholder nodes, native project or extra currency.
